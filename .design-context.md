## Design Context

### Users
Watchtower is for casual vibe coders who want a visual, low-friction way to understand what their coding agents are doing. They are likely running multiple AI assistants, submitting tasks, and checking progress while staying in a creative flow. The interface should make agent activity feel legible and alive without requiring operational discipline or dashboard expertise.

### Brand Personality
The product personality is chill, playful, and capable. It should feel like a relaxed coding companion that turns background agent work into something visible and satisfying. The emotional target is calm curiosity: users should feel oriented, lightly entertained, and confident that they can see what each agent is doing.

### Aesthetic Direction
Keep the current top-down simulation and control-panel structure, but push it toward a slightly cartoonish game feel rather than a purely technical command center. Agent icons can be rounded, expressive, colorful, and distinct, but not childish or toy-like. Support both dark and light modes; dark mode can remain the default, while light mode should feel soft and readable rather than stark. Avoid marketing/SaaS landing-page visuals and avoid heavy neon cyberpunk styling. Use color to distinguish agents and states, but keep the palette balanced enough that the task flow remains easy to scan.

### Design Principles
1. Make agent work visible at a glance: every task state should have a clear spatial, motion, or status cue.
2. Keep the vibe chill: use gentle motion, readable contrast, and friendly shapes instead of urgent alerts or aggressive styling.
3. Make it game-like, not childish: add character and delight through icons, movement, and feedback while preserving a capable coding-tool feel.
4. Preserve fast keyboard flow: visual polish should not slow down submitting tasks, targeting agents, or reading status.
5. Design for theme parity: new UI elements should work in both dark and light modes from the start, with shared semantic colors where possible.
